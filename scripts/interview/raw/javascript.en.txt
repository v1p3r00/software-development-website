### Q1
LEVEL: junior
TOPIC: Hoisting
TYPE: output
QUESTION: What is printed to the console?
CODE:
console.log(a);
var a = 10;
ENDCODE
A) `undefined`
B) `10`
C) `ReferenceError`
D) `null`
ANSWER: A
EXPLANATION: The `var` declaration is hoisted to the top of the function or global scope, but the assignment is not. Therefore, the code behaves as if `var a;` appeared before the `console.log` call. At that point, the value is still `undefined`.
###END

### Q2
LEVEL: junior
TOPIC: let and const
TYPE: output
QUESTION: What happens when the code is executed?
CODE:
console.log(x);
let x = 5;
ENDCODE
A) `undefined` is printed
B) `5` is printed
C) A `ReferenceError` is thrown
D) `null` is printed
ANSWER: C
EXPLANATION: The `let` declaration is also hoisted, but it remains in the Temporal Dead Zone (TDZ) until initialization. Therefore, accessing it before the declaration results in a `ReferenceError`. This differs from the behavior of `var`.
###END

### Q5
LEVEL: junior
TOPIC: == and ===
TYPE: trap
QUESTION: Which statement is true about the following expressions?
CODE:
console.log(0 == false);
console.log(0 === false);
ENDCODE
A) Both are `true`
B) Both are `false`
C) The first is `true`, the second is `false`
D) The first is `false`, the second is `true`
ANSWER: C
EXPLANATION: The `==` operator can perform type coercion, so `0 == false` is true. The `===` operator does not perform implicit type coercion; the left side is a `number` and the right side is a `boolean`, so the result is `false`. In modern JavaScript, `===` is generally the clearer choice.

### Q25
LEVEL: medior
TOPIC: Promises

B) `B A C`
