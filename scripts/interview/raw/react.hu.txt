### Q1
LEVEL: junior
TOPIC: JSX & rendering
TYPE: output
QUESTION: Mit jelenít meg az alábbi React komponens?
CODE:
function App() {
  const name = "Anna";
  return <h1>Hello, {name}!</h1>;
}
ENDCODE
A) Hello, name!
B) Hello, Anna!
C) Hello, {name}!
D) Hibát dob, mert változót nem lehet JSX-ben használni.
ANSWER: B
EXPLANATION: A JSX kapcsos zárójelei JavaScript-kifejezés kiértékelését teszik lehetővé, ezért a `name` változó értéke, vagyis `Anna`, kerül a `<h1>` elembe. A gyakori téves válasz azért csábító, mert a JSX első ránézésre HTML-szerűnek tűnik, de valójában JavaScriptbe ágyazott szintaxis.
###END

### Q2
LEVEL: junior
TOPIC: Components & props
TYPE: behavior
QUESTION: Mi jelenik meg az oldalon az alábbi komponens használatakor?
CODE:
function Greeting({ name }) {
  return <p>Szia, {name}!</p>;
}

function App() {
  return <Greeting name="Péter" />;
}
ENDCODE
A) Szia, name!
B) Szia, undefined!
C) Szia, Péter!
D) A `Greeting` nem kap propsot, ezért hibát dob.
ANSWER: C
EXPLANATION: A `name="Péter"` propként átadódik a `Greeting` komponensnek, amely a paraméterben destructuringgel kiveszi a `name` értéket. Ezért a renderelt szöveg `Szia, Péter!` lesz. Az `undefined` azért tűnhet valószínűnek, mert a komponens nem használja közvetlenül a `props.name` formát, de a destructuring ettől még teljesen érvényes.
###END

### Q3
LEVEL: junior
TOPIC: State & useState
TYPE: output
QUESTION: Mi lesz a gomb megnyomása után a konzolban?
CODE:
function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
    console.log(count);
  }

  return <button onClick={handleClick}>{count}</button>;
}
ENDCODE
A) Mindig `0`
B) `1`
C) `undefined`
D) A React mindig az új state értékét írja ki, tehát `1`
ANSWER: A
EXPLANATION: A `setCount` ütemezi a state frissítését, de ugyanabban az event handler futásban a `count` változó még az aktuális renderhez tartozó értéket, vagyis `0`-t tartalmaz. A következő renderben lesz `count` értéke `1`. Az `1` azért csábító, mert a fejlesztő intuitívan úgy gondolhatja, hogy a setter azonnal módosítja a változót.
###END

### Q4
LEVEL: junior
TOPIC: useEffect & lifecycle
TYPE: behavior
QUESTION: Mikor fut le az alábbi effect?
CODE:
function App() {
  useEffect(() => {
    console.log("effect");
  }, []);

  return <div>Hello</div>;
}
ENDCODE
A) Minden render előtt
B) Minden render után
C) Az első render után, majd minden state-változáskor
D) A komponens mountolása után, egyszer az adott mount életciklusában
ANSWER: D

Fejlesztői Strict Mode környezetben React extra ellenőrzési célból további effect setup/cleanup ciklust is végrehajthat, ezért fejlesztésben a konzolban több futás látszódhat. A „minden render után” azért csábító, mert dependency array nélkül valóban minden commit után futna az effect.
###END

### Q12

QUESTION: Egy komplex React alkalmazásban egy nagy navigációs váltás egyszerre módosítja az URL-hez kötött state-et és egy lassan renderelő UI-rész állapotát. B) Az összes komponenst egyetlen Suspense boundary alá kell helyezni fallback nélkül.
