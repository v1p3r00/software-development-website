### Q1
LEVEL: junior
TOPIC: Java Core & OOP
TYPE: behavior
QUESTION: What happens when we call the `makeSound()` method on the `Dog` object in the following code?
CODE:
class Animal {
    void makeSound() {
        System.out.println("animal");
    }
}

class Dog extends Animal {
    @Override
    void makeSound() {
        System.out.println("dog");
    }
}

Animal animal = new Dog();
animal.makeSound();
ENDCODE
A) `animal` is printed because the variable type is `Animal`.
B) `dog` is printed because the actual type of the instance is `Dog`.
C) A compilation error occurs because a `Dog` method cannot be called through an `Animal` reference.
D) A runtime `ClassCastException` occurs.
ANSWER: B
EXPLANATION: Java uses dynamic dispatch for overridden instance methods. The reference is declared as `Animal`, but the actual object is a `Dog`, so `Dog.makeSound()` is invoked at runtime. The common incorrect answer is tempting because the declared reference type really is `Animal`, but it does not determine which overridden instance method implementation executes.
###END
