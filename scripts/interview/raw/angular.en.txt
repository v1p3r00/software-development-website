### Q1
LEVEL: junior
TOPIC: Components & templates
TYPE: behavior
QUESTION: What is displayed on the screen with the following Angular component template?
CODE:
title = 'Angular';
ENDCODE
A) Angular
B) title
C) {{ title }}
D) Nothing, because the property is not defined as a signal
ANSWER: A
EXPLANATION: Angular interpolation reads the current value of the component's `title` property and displays it in the template. The most common incorrect answer is tempting because modern Angular examples often use signals, but traditional property binding is still fully supported.

### Q197
LEVEL: senior
TOPIC: Signals
TYPE: production
QUESTION: An effect reacts to a signal change and then modifies that same signal. Why can this be architecturally dangerous?
CODE:
const count = signal(0);

effect(() => {
  const value = count();
  count.set(value + 1);
});
ENDCODE
A) It can create a reactive feedback loop, so `computed()` is generally more appropriate for derived state.
B) An effect cannot read signals.
C) `set()` always shuts down the Angular application.
D) An effect can only be created from an HTTP interceptor.
ANSWER: A
EXPLANATION: The effect reads the `count` signal and then modifies that same signal, which can trigger another reaction and lead to a feedback loop or otherwise difficult-to-follow reactive behavior. For derived state, `computed()` is generally a cleaner model. Writing to a signal is not inherently forbidden, but writing back to state that the effect itself reads must be designed carefully.
